# 爆款内容逆向拆解 · 编排器

把一条（或一组）爆款内容从视觉表层一路拆到最深的成交驱动力，然后产出你自己能放大优势的创作蓝图。

## 什么时候用这个编排器 vs 直接用子 skill

| 场景 | 用什么 |
|------|--------|
| 完整逆向一条爆款（从看到产出脚本） | **本编排器**（跑完整十一层漏斗） |
| 只想分析画面/镜头/视觉工艺/图文设计 | 直接用 `viral-visual-forensics` |
| 只想拆出镜者的表现力/镜头感/语气语调 | 直接用 `viral-performance-audit` |
| 只想拆钩子和叙事结构 | 直接用 `viral-structure-decoder` |
| 只想挖痛点/欲望/人群心理 | 直接用 `viral-psychology-excavator` |
| 只想分析评论区（挖用户痛点/欲望/画像） | 直接用 `viral-comment-intelligence` |
| 只想分析行为数据（完播/点赞/转发/千人千面） | 直接用 `viral-behavior-signals` |
| 想从行为/内容反推某人的核心欲望和画像 | 直接用 `viral-person-decoder` |
| 想拆两人聊天记录（双方欲望/状态/对齐/下一步动作） | 直接用 `viral-dialogue-decoder` |
| 只想拆一段**纯文案**（广告词/标题/公众号或小红书正文/邮件/slogan）：打中谁+激发什么情绪行动+怎么优化欲望命中 | 直接用 `viral-copy-decoder` |
| 已有拆解+画像，要 AI 生成自己的内容 | 直接用 `viral-content-generator` |
| 已有拆解结果，要做放大方案和脚本 | 直接用 `viral-amplification-architect` |
| **发布前**预测一条内容会打中谁/激发什么情绪行动，或预测一个主体接下来的状态 | **引擎侧预测出口** `cce_predict.py`（见「引擎侧：CCE 预测出口」节） |

编排器的价值在于**强制走完整漏斗**，避免只拆表层就动手（这是最常见的伪拆解）。

## 十一层漏斗总览（10 个子 skill + 编排器）

```
原始内容 + 评论区数据 + 行为数据
   │
   ▼
L1 视觉取证 (visual-forensics)            ← 它长什么样：镜头/光影/节奏/文字/音乐/图文设计
   │
   ▼
L1.5 表现层审计 (performance-audit)        ← 他怎么演：肢体/声音/镜头感/形象/情绪表达（仅有出镜者时）
   │
   ▼
L2 结构解码 (structure-decoder)            ← 它怎么讲：钩子公式/叙事弧/节奏曲线/开环
   │
   ▼
L3 心理挖掘 (psychology-excavator)         ← 它戳什么：痛点/欲望/恐惧/身份/触发器/人群/表现-心理映射
   │
   ▼
L3.5 评论智能 (comment-intelligence)       ← 观众自己说：评论分类/欲望映射/画像/触发回溯（交叉验证L3）
   │
   ▼
L3.6 行为信号 (behavior-signals)           ← 观众怎么做：完播/点赞/转发/收藏→动机/千人千面/人群画像
   │
   ▼
L4 放大架构 (amplification-architect)      ← 怎么赢：保留什么/升级什么/差异化什么/脚本
   │
   ▼
L4.5 人的拆解 (person-decoder)             ← 人想要什么：从所有信号反推核心欲望+稳定画像（终极层）
   │
   ▼
L4.6 对话拆解 (dialogue-decoder)           ← 两人怎么博弈：bid-响应配对/欲望对齐/下一步动作（有双人对话时）
   │
   ▼
L5 内容生成 (content-generator)            ← 做出来：AI生成视频脚本/文案/标题/图片/图文/标签（闭环产出）
   │
   ▼
交付物四件套：拆解报告 + 差异化蓝图 + 可拍脚本 + 人群画像&AI内容套件
```

**三层交叉验证**（L3/L3.5/L3.6）：L3 从内容推断观众心理（猜），L3.5 从评论验证（观众自己说），L3.6 从行为数据验证（观众做）。三层交叉一致 = 推断可靠；不一致 = 以评论/行为证据为准修正 L3。

**闭环逻辑**（L1→L5）：拆解别人的爆款（L1-L3.6）→ 理解人想要什么（L4.5）→ 设计放大策略（L4）→ AI 生成自己的内容（L5）→ 发布后用 L3.5/L3.6 验证效果 → 反馈修正画像 → 优化下一轮生成。这才是完整闭环。

**L1.5 是否必跑**：内容有出镜者（真人/数字人对镜头说话或表演）→ 必跑。纯视觉奇观/纯图文/无人出镜 → 跳过，标注「无表现层」。

## 两条一等路径：短视频 vs 图文（Step 0 判定，全程路由）

短视频和图文是**两条并行的一等路径，不是主次/变体关系**。视频路径以视觉逐帧取证领衔（L1 最重、有时间轴/钩子窗/逐帧）；图文路径以**文本通道领衔**（标题+正文+评论=引擎最强通道）。**只有 L1/L2 走各自的子模式，L3 及以下（心理/人/放大/生成）完全共用——不新建任何重复 skill。**

### 为什么图文单独成路（不是视频的变体）

图文（小红书笔记）的结构和视频根本不同：

- **无时间轴 / 无钩子窗 / 无逐帧**。不是「前 3 秒」决定完播——是**封面第一眼 + 标题**决定点击，**首图 + 首段**决定展开，**信息梯度 + 收藏诱因**决定收藏。
- **载体是静态**：封面图 + 标题 + 正文 + 图片序列（多图）。阅读是**用户自控节奏**（可停可回翻），不是被动流。
- **文本是主干，图片是补充**：标题/正文/评论是**文本原生 = 引擎最强通道**（受众级共振读出 ρ≈0.5 从文本来，已证；对账定案「文本原生充分 / 视频原生须视频解析」）。所以**图文的引擎骨干比视频更硬**——视频有一部分靠视觉推断（弱通道），图文几乎全走文本强通道。图片承担封面吸引力 + 配图信息 + 排版观感，need 层细节按需解析。

### 图文路径的层映射

| 层 | 视频路径 | 图文路径（本分支） |
|----|----------|--------------------|
| **L1 视觉取证** | 逐帧镜头清单/运镜/节奏曲线/音频层 | **图文子模式**（非逐帧）：封面吸引力（第一眼读懂度/主视觉/文字hook/承诺-展示差）+ 配图信息（每张图功能/图集叙事）+ 图文排版（字体/层级/配色/留白）。用 `viral-visual-forensics` 的「图文内容」段（见其 `references/image-text-design-system.md`）。配图逐张细节属 need 层，按需解析。 |
| **L1.5 表现层** | 出镜者肢体/声音/镜头感 | **通常跳过**（图文一般无出镜表演）。仅封面/图集是真人出镜口播式才跑，否则标「无表现层」。 |
| **L2 结构解码** | 钩子(前3秒)/叙事弧/时间轴节奏/开环 | **图文结构子模式**：标题公式（标题党公式）+ 首图钩子（封面第一眼=图文的「前3秒」）+ 正文信息结构（信息梯度/阅读结构）+ 收藏诱因。钩子分类学和叙事弧**复用**，触发窗从「前3秒」改「封面+标题」，时间轴节奏改「阅读结构+翻页停留」。用 `viral-structure-decoder` 的「图文结构子模式」段。 |
| **L3 心理挖掘** | 复用（模态无关） | **直接复用**。标题+正文+评论走**文本通道**——引擎最强通道，比视频的视觉推断更硬。 |
| **L3.5 评论智能** | 复用 | **直接复用**。评论=文本原生决策面（已证），图文评论区同样是观众欲望的直接证据。 |
| **L3.6 行为信号** | 完播/点赞/转发 | **复用但换指标**：图文核心信号是**收藏率 + 点赞率 + 涨粉**（收藏=图文的完播等价物；收藏型 vs 评论型两极已证）。绝对收藏量=脏真值，不事前预测（封路，见下）。 |
| **L4.5 人的拆解** | 复用（终极层） | **直接复用**（模态无关）。 |
| **L4 放大架构** | 复用 | **直接复用**。放大矩阵对图文 = 封面/标题/正文/图集的变量矩阵。 |
| **L5 内容生成** | 复用 | **直接复用**。图文套件（封面 + 标题5候选 + 正文 + 图片序列 + 标签）本就在 L5 产出清单里。 |

### 图文逆推走引擎文本通道（主逆推路径）

图文的标题/正文/评论全是文本原生，**逆推走 `cce_predict.py fragment`**：把标题 + 正文（+ 高赞评论）作为文本喂给 fragment 出口，拿「这段文本打中谁 / 激发什么情绪与行动倾向」的**分布 + 置信**（见下文「引擎侧：CCE 预测出口」节）。图片是补充：need 层细节（配图具体信息/视觉签名）只在文本不足或需视觉证据时解析。

### 图文闭环（封面/标题/正文 → 心理 → 放大 → 生成）

```
封面图 + 标题 + 正文 + 图片序列 + 评论
   │
   ▼
L1 图文视觉取证：封面吸引力 + 配图信息 + 排版（非逐帧）
   │
   ▼
L2 图文结构：标题公式 + 首图钩子 + 正文信息结构 + 收藏诱因
   │
   ▼
L3/L3.5/L3.6 心理（文本通道领衔）：标题+正文+评论逆推欲望/人群/触发器 → cce_predict fragment 交叉验证
   │
   ▼
L4.5 人的拆解：反推核心欲望 + 稳定画像（模态无关）
   │
   ▼
L4 放大架构：封面/标题/正文/图集的放大矩阵 + 差异化
   │
   ▼
L5 内容生成：封面 + 标题5候选 + 正文 + 图片序列 + 标签（图文套件）
```

### 图文模式的诚实边界（继承对账封路条款）

- ✅ **已证/可做**：图文正文/标题/评论文本充分（文本原生=引擎最强通道，ρ≈0.5 已证）→ 能做「**打中谁 + 结构优化**」（受众级共振读出、欲望/人群逆推、标题/封面/正文的结构性放大）。
- 🚫 **封路（禁做）**：**禁单帖爆款 / 收藏量 / 播放曝光量的事前预测**（脏真值=算法+粉丝基数支配，与视频路径同一条封路）。收藏「诱因」的**结构分析**可做，收藏「量」的**数值预测**不可做。
- 📐 **纪律**：逆推=推断非读心；全占比 + 序稳健（不卡精确阈值）；粒度=受众级可预测、单条不可预测。

### 与视频路径如何共存不冲突

- **共用同一套子 skill + 同一套 L3+ 层**：图文只在 L1/L2 走子模式分支，L3 及以下完全共用，零重复 skill。
- **形态在 Step 0 判定一次，全程路由**：视频→逐帧/时间轴路径；图文→封面/标题/正文文本路径。下面「执行流程」以视频为默认叙述，图文按本节的层映射就地替换 L1/L2 维度。
- **混合内容**（如小红书视频笔记）：按主载体判定；视频为主走视频路径、图文为主走图文路径，另一模态作补充证据。

## 执行流程

### Step 0 · 确认输入和目标

先跟用户确认三件事（信息齐全可跳过）：

1. **拆解对象**：内容链接 / 本地文件 / 平台+账号+内容描述。如果只有描述没有素材，标注「无素材拆解，结论为推测」
2. **平台和形态（路由闸门）**：视频 / 图文 / 直播切片？哪个平台？**形态在此判定一次，决定走视频路径还是图文路径**——图文（小红书图文笔记）走「两条一等路径」节的图文层映射（L1/L2 走图文子模式，L3 及以下共用）。混合内容按主载体判定。
3. **目标**：纯学习？还是要在同领域出自己的爆款？目标决定 L4 产出深度

### Step 1 · L1 视觉取证

> **图文模式**：跳过逐帧/镜头/音频，走 `viral-visual-forensics` 的「图文内容」子模式（封面吸引力 + 配图信息 + 图文排版），产出图文设计系统报告。详见「两条一等路径」节。

调用 `viral-visual-forensics` skill。产出：
- 镜头清单（逐镜：时长/景别/运镜/主体/文字/转场）
- 视觉工艺判断（实拍 / 3D渲染 / 混合 / 手机直拍）
- 节奏曲线（每 X 秒一个变化点，画成时间轴）
- 音频层（音乐类型/BPM/音效节奏/人声语速）
- 第一印象结论：这条内容的视觉「抓人」靠什么

### Step 1.5 · L1.5 表现层审计（仅有出镜者时）

- 触发条件：内容有出镜者（真人/数字人/动画角色对镜头说话或表演）→ 必跑；纯视觉奇观/纯图文/无人出镜 → 跳过并标注「无表现层」
- 调用 `viral-performance-audit` skill，产出摘要：肢体语言 / 声音表达 / 镜头感 / 形象管理 / 情绪表达质量 + 表现层结论（换个人演会丢什么 = 表现层发动机）
- L1.5 产出直接喂给 L3 的「表现-心理映射」模块（表现→心理映射候选清单只保留在 `viral-performance-audit/SKILL.md` 结尾「给 L3 的馈赠」一处）
- 完整维度与分类库见 `viral-performance-audit/SKILL.md` 及其 `references/`（body-language-atlas.md / vocal-delivery-guide.md）

### Step 2 · L2 结构解码

> **图文模式**：走 `viral-structure-decoder` 的「图文结构子模式」——标题公式 + 首图钩子（=图文的前3秒）+ 正文信息结构 + 收藏诱因；钩子分类学复用，时间轴节奏替换为阅读结构。详见「两条一等路径」节。

调用 `viral-structure-decoder` skill。产出：
- 钩子分类（套用钩子分类学，见该 skill 的 references/hook-taxonomy.md）
- 叙事弧类型（问题-放大-解决 / 清单种草 / 过程展示 / 对比反差 / 故事弧 / 情绪共鸣 / 纯视觉奇观）
- 节奏分析（开环数量和位置 / payoff 时机 / 信息密度曲线）
- 前3秒完整还原（逐帧：看到什么+听到什么+读到什么文字）

### Step 3 · L3 心理挖掘（最深一层，用户最看重）

- 调用 `viral-psychology-excavator` skill——整个组合的核心层
- 产出摘要：痛点地图（四层级）/ 欲望解码 / 内容胃口 / 人群画像 / 触发器矩阵 / 情绪弧线 / 成交驱动力；跑过 L1.5 时另附表现-心理映射（映射候选见 `viral-performance-audit/SKILL.md` 结尾「给 L3 的馈赠」）
- 完整模块定义见 `viral-psychology-excavator/SKILL.md`；欲望 9 类定义见其 `references/desire-taxonomy.md`；触发器分类见其 `references/trigger-library.md`

### Step 3.5 · L3.5 评论智能（观众欲望的直接证据）

如果内容有评论区数据（抓取或手动复制），调用 `viral-comment-intelligence` skill。产出：

- **评论分类分布**：9 类评论（痛点表达/欲望表达/社会认同/身份信号/个人故事/情绪宣泄/提问求解/异议争论/幽默玩梗）的占比和高赞集中度
- **核心欲望验证**：高赞评论映射到的核心欲望，和 L3 推断做交叉验证
- **评论者画像**：从评论语言推断 2-3 个评论者子群体的画像
- **情感集群模式**：评论区是一致共鸣/两极分化/情绪递进/发散/情绪转化
- **触发回溯**：高赞评论被内容的哪个元素触发

**L3.5 的价值**：L3 是从内容猜观众心理，L3.5 是让观众自己说。两层交叉验证——一致则可靠，不一致以评论为准。

评论获取优先级：
1. **JustOneAPI（推荐·全平台结构化数据）**：`pip install justoneapi`，支持抖音/小红书/TikTok/Instagram/YouTube/Bilibili。一次调用同时拿视频详情(stats)+评论+作者信息
2. `/Volumes/data/lead-miner/unified_scraper.py "URL" --max 100`（TikTok/YouTube 无登录 Playwright）
3. 已登录的 Codex 内置浏览器手动复制（兜底）

读 `viral-comment-intelligence/references/comment-taxonomy.md` 获取 9 类评论的完整识别模板。

### Step 3.6 · L3.6 行为信号（算法和欲望的中间层）

如果有创作者后台数据或公开数据（播放/点赞/评论/转发数），调用 `viral-behavior-signals` skill。产出：

- **行为信号解读**：完播率/点赞率/评论率/转发率/收藏率/关注转化率逐个分析
- **信号组合→内容类型**：用信号组合表判断内容属于哪种类型（沉浸享受/共鸣感动/话题争议/钩子型/实用工具/人设建立/现象级爆款）
- **千人千面分析**：算法可能给内容打了什么标签→推给了谁→推量效率→破圈建议
- **行为人群画像**：从时间分布/地域分布/行为深度推断人群特征

**L3.6 的价值**：行为信号是欲望的可观测投影。观看和点赞是被动行为，评论是主动输出——三层信号组合才能完整理解观众。同时理解千人千面机制，才能知道内容会被推给谁。

读 `viral-behavior-signals/references/algorithm-signal-map.md` 获取各平台算法权重详细映射。

### Step 4 · L4 放大架构 + 脚本生成

调用 `viral-amplification-architect` skill。

**前置质量门**：L1-L3.6 全部跑完后，用 `references/scoring-rubric.md` 评分。总分 < B 级（<25/35 或 <22/30）→ 不进 L4，先回去补薄弱层。基础不牢，放大方案会跑偏。

产出：

- **可复用核心**：这条爆款的「发动机」是什么（一句话讲清，不是罗列所有元素）
- **放大矩阵**（复用 Meta 1×6×5=30 框架的逆向用法）：
  - 哪个变量是这条爆款的命脉（动了它就不火的那个）
  - 哪些变量可以安全替换（换了还是同一条逻辑但换皮）
  - 哪些变量可以升级（比原版做得更好）
  - 哪些变量必须差异化（避免搬运，建立自己的辨识度）
- **差异化定位**：你的版本和原版的核心区别是什么（一句话，用于团队对齐）
- **脚本骨架 + 放大决策要点**（本层只出骨架，完整成稿走 L5 `viral-content-generator`）：
  - 逐镜分镜结构（镜号/时长/画面/文字/音频/表演指导的骨架定义）
  - 文案要点（口播要点 + 屏幕文字方向 + 标题/描述/标签方向）
  - 钩子候选方向（至少 3 个前3秒版本，标注各自的心理触发路径）
- **放大前 gate**（5 条，唯一权威定义见 `viral-amplification-architect/SKILL.md` 模块五）：验证数据 / 指标不偏科 / 可一句话复述 / 非单点红利 / 发动机可移植

读 `viral-amplification-architect/references/amplification-matrix.md` 获取放大矩阵模板。

### Step 4.5 · L4.5 人的拆解（终极层——理解人想要什么）

调用 `viral-person-decoder` skill。这是整个体系的终极目的——不只是拆内容，而是拆**人**。

从 L1-L3.6 的所有信号反推目标人群的核心欲望：

- **信号归类**：把所有可观测信号（内容消费/行为数据/评论表达）归类到 9 种核心欲望（唯一权威定义：`viral-psychology-excavator/references/desire-taxonomy.md`，与引擎侧 `config/desire_taxonomy.json` 同源，`assert n==9` 守卫）
- **核心欲望排序**：计算每种欲望的权重，找出前 2-3 名 = 这类人的核心欲望结构
- **稳定画像**：从核心欲望推导完整人群画像（人口特征/心理特征/内容偏好/决策模式）
- **内容击中公式**：触发器 × 主题 × 形态（内容匹配的展开与执行职责归 L5 `viral-content-generator`）

**核心认知**（用户原话）：需求分层次但都对应原始欲望，人跟随着欲望走。所有内容/表情/音乐/动作都是欲望的外化。理解了欲望，才能精准定位人群，才能生成击中欲望的内容。

### Step 4.6 · L4.6 双人对话拆解（仅有双人对话记录时）

- 触发条件：输入包含两人聊天记录（截图/文本，仅限用户自己参与或已获授权的对话）→ 跑；无对话数据 → 跳过并标注「无对话模态」
- 调用 `viral-dialogue-decoder` skill，产出摘要：对话结构+turn-taking 力学 / bid-响应配对与关系温度曲线 / 双向欲望对齐度矩阵（交集/错位/单向）/ 关系阶段判定 / 下一步最优动作+风险警告。三场景预设：亲密关系、商业跟单（回应分化=购买意向温度）、团队沟通
- 完整分类学见 `viral-dialogue-decoder/references/bid-response-taxonomy.md`；与 L4.5 联动：对话中单方的欲望证据可喂给 L4.5 做稳定画像，L4.5 已有画像可作 L4.6 先验

### Step 5 · L5 内容生成（闭环产出——AI 生成自己的爆款）

调用 `viral-content-generator` skill。把拆解和画像转化成自己的内容。

基于 L4 的放大矩阵 + L4.5 的人群画像 + L3 的核心欲望，用 AI 生成完整内容套件：

- **视频脚本**：分镜表 + 口播文案 + 钩子候选（锚定核心欲望 + 保留爆款发动机）
- **文案**：标题（5个候选）/ 描述 / 评论引导 / 评论区置顶
- **图片提示词**：封面/产品/氛围/图文搭配的 AI 图片生成提示词
- **图文搭配**（小红书）：封面+正文+图片序列+标签的完整结构
- **跨平台版本**：同一拆解结果生成不同平台的适配版本

**闭环**：发布后用 L3.5（评论）+ L3.6（行为数据）验证效果 → 反馈给 L4.5 修正画像 → 优化下一轮 L5 生成。


## JustOneAPI 数据源（推荐·真实爆款结构化数据）

JustOneAPI 是社交媒体数据抓取平台，能从抖音/小红书/TikTok/Instagram/YouTube/Bilibili 等平台拉取真实结构化数据（视频详情/评论/用户画像/搜索结果）。用真实爆款数据做拆解比合成案例有效得多。

### 快速接入

```python
import justoneapi

c = justoneapi.JustOneAPIClient(token='<your_token>')

# 搜索爆款
results = c.douyin.search_video_v4(keyword='美食探店', sort_type=0)

# 拿视频详情（stats + author + desc）
detail = c.douyin.get_video_detail_v2(video_id='<aweme_id>')
stats = detail.data['aweme_detail']['statistics']

# 拉评论
comments = c.douyin.get_video_comment_v1(aweme_id='<aweme_id>', page=1)
```

### 支持的平台

- **抖音** (`c.douyin`)：search_video_v4 / get_video_detail_v2 / get_video_comment_v1 / get_user_detail_v3 / hot_search_v1
- **小红书** (`c.xiaohongshu`)：笔记搜索/笔记详情/笔记评论
- **TikTok** (`c.tiktok`) / **Instagram** (`c.instagram`) / **YouTube** (`c.youtube`) / **Bilibili** (`c.bilibili`)

### 实战工作流

1. `search_video_v4(keyword=<赛道关键词>)` 找同领域爆款
2. 按 `digg_count` 排序，挑 3-5 条高赞内容
3. 对每条 `get_video_detail_v2` + `get_video_comment_v1` 拿完整数据
4. 把 `desc` + `stats` + `comments` 组装成 skill 输入，走 L1→L5 拆解

**真实数据校准价值**（2026-07-21 验证）：用真实爆款的真评论做拆解，M3 能挖出评论里观众自己都没意识到的集体潜意识。例如 Bobo 170 万赞拆解中，最高赞评论（9万赞）直接暴露了观众真正想要的不是「中餐征服世界」而是「干净安静有人情味的世界」——食物是特洛伊木马，小镇才是本体。

## 校准发现与使用须知（2026-07-21 系统性校准测试结果）

本 skill 组合经过 19 次校准测试（6类校准维度），发现以下特性，使用时需注意：

### 稳定性（同一内容多次解析）
- **叙事型内容**（MC建造/知识口播/生活方式）：核心欲望识别 **3/3 完全一致**，可信赖单次结果
- **氛围型内容**（纯音乐/无叙事视觉）：核心欲望识别 **2/3 一致**，第一次和第三次一致但第二次不同——建议对这类内容跑2次取交集
- 人群画像和发动机描述虽然措辞不同但语义高度一致（稳定性好）

### 区分度（不同内容能否拆出不同结论）
- **跨类型对比**：✅ 优秀（4种类型拆出3种不同第一欲望）
- **同类对比**：⚠️ 需注意（2条音乐类内容都拆出归属欲——可能是同类本质相同，也可能是灵敏度不足）
- **建议**：同类内容对比时，重点看 L4（放大方案）的差异化度，而非 L3 欲望的差异

### 已知盲区
1. **情感模糊内容**：纯音乐/纯风景/无叙事的内容，L3 稳定性下降（已通过「内容确定性等级」改进）
2. **无评论数据**：L3.5 跳过时，L3 的推断缺乏验证，可靠性降低（建议至少抓5条评论）
3. **广告内容**：skill 能拆但发动机识别偏向「情感发动机」，对「价格发动机」「稀缺性发动机」不够灵敏

### JSON 结构化输出
如需将拆解结果用于自动化流程，注意 M3 的 JSON 提取有 ~11% 失败率，建议加容错重试。


## 引擎侧：CCE 预测出口（2026-07-22 新增）

本 suite 的心理层（L3/L3.5/L3.6/L4.5）底下是**认知因果引擎（CCE）**，位于 `$CCE_ROOT/`。suite 负责拆解与生成（事后闭环），引擎负责**事前预测**——这是漏斗此前缺失的出口。两侧词表同源：欲望9类=Desire、需求17类=Goal、情绪13类、行动倾向7类（死映射见引擎 `results/cce_modules/01_ontology.md`）。

**已验证的预测能力**（带外部真值，勿超范围宣称）：
- **受众/创作者级共振读出（已证 · 外部真值）**：引擎从内容文本逆推的四层心理分布，经冻结线性读出，能以 **ρ≈0.5（95%CI 0.28–0.69）** 预测创作者受众的实用共振强度（藏赞比），跨 12 品类、体量无关、两轮预注册、仪器冻结（`results/cce_creator_signal_pooled.json`）。行业对照：HypeAuditor/CreatorIQ 零公开效度，学术匹配基线 r 0.1–0.3。
- **跨时间个人预测（已证 · 4 次独立复现）**：desire/need/emotion 层个体身份预测 SS 0.44–0.76，显著胜人群基线；**action 层无个人化增益，用人群 prior 即可**（`results/cce_phase3_gate_report.md`）
- 节点内因果链预测（上游→情绪/行动）：SS>0，bootstrap CI 不跨零；跨模型硬档仍 SS>0（`results/cce_phase1_prediction.md`）
- 对话情绪耦合（已证 · 真实双人对话）：一方情绪→另一方情绪传染 P=0.97（喂给 L4.6 dialogue-decoder）
- 标定参数（人群 prior、n_eff 收窄~1/k、噪声位）：`results/cce_param_calibration.md`

**粒度纪律（硬边界 · 封路）**：可预测的是**创作者/受众级**共振与**个体级**身份结构；**单帖级不可预测**——单帖爆款/播放量/最佳发布时机受算法+粉丝基数+运气支配，已三重实锤（SMTPD/MusicLab/E1）不可事前预测，禁止任何「这条会爆」的宣称。fragment 出口给的是「这段文本会打中谁 / 激发什么情绪与行动倾向」的**分布+置信**，不是单帖爆款概率。

**用法**：
```bash
cd $CCE_ROOT && source .env
# 发布前预测：这条内容/文案会打中谁、激发什么情绪与行动倾向
python3 scripts/cce_predict.py fragment --text "<草稿或碎片>" --n 5
# 主体预测：这个人接下来的四层状态分布（需先有时间轴 teardown 数据）
python3 scripts/cce_predict.py subject --id <sec16或昵称>
```
输出恒带 confidence/uncertainty/evidence_count/last_updated/fresh_until/provenance 元数据；全占比原则——只给分布+置信，不给固定点结论。真值状态：**创作者/受众级共振读出已有外部真值背书（藏赞比 ρ≈0.5，两轮预注册）**，个体级四层结构已 4 次复现（SS 0.44–0.76），对话情绪耦合已证（P=0.97）；fragment/subject 预测以模型逆推共识为主，单帖绝对数值无金标准（本就不可预测）。

**纯文案的产品化前端**：拆一段现成文案（广告词/标题/正文/邮件/slogan）「打中谁 + 激发什么情绪行动 + 怎么优化欲望命中」时，用 `viral-copy-decoder`——它是 `fragment` 出口的产品化封装（把引擎四层读数翻成序稳健的受众画像+优化建议），并写死了同一套封路纪律（不承诺会火/只做受众级/序稳健）。fragment 是引擎原语，copy-decoder 是给纯文本场景的应用层。

## 关键纪律（铁律）

1. **禁止搬运**。逆向是为了理解发动机原理，不是复制外壳。差异化定位必须回答「我的版本凭什么不是搬运」
2. **事实核查**。所有数据（播放量/阈值/统计）必须标源。无源的标「定性结论，无数据支撑」。绝不编造百分比。2026-07-10 曾删除伪造的「84.3%爆款有钩子」统计——那条数据来自无方法论的个人网站
3. **失败视觉只作负面约束**。逆向竞品时只抽象功能结构，不复刻其视觉语言。原版的构图/配色/隐喻不作你的正向创意种子
4. **激活钩子**。每次用完这个 skill 组合，用 `memory_meta(action='feedback', skill_id=..., outcome=...)` 报告结果。避免变成下一个「写了没用过」的 skill
5. **质量评分**。L1-L3.6 全部跑完后必须用 `references/scoring-rubric.md` 逐层评分。总分 < B 级不进 L4。评分由 `$CCE_ROOT/scripts/benchmark.py` 自动执行或人工对照量规
6. **素材获取**。需要下载视频/图文素材时，先查 `unified_scraper.py`（位于 `/Volumes/data/lead-miner/`，无登录 Playwright 方案，支持 TikTok/YouTube）。抖音/小红书/Instagram 可能需要手动下载或已登录浏览器

## 何时拆成多次执行

- 单条视频深度拆解：一次会话跑完十一层漏斗
- 批量拆解同领域 10+ 条：先批量跑 L1+L2（快），筛出 2-3 条代表性爆款再跑 L3+L4（深）
- 只想要脚本不要完整拆解：直接进 L4，但必须先口头确认 L3 的心理假设（否则脚本无根）
